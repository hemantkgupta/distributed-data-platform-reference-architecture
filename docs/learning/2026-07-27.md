## What I Learned

Auto Loader has two kinds of durable state: checkpoint state and schema state. The checkpoint tracks discovered files and stream progress. The schema location tracks inferred schema and schema evolution. Losing either one turns a controlled incremental pipeline into a replay or restart incident.

`_rescued_data` is not an error bucket for operators to ignore. It means the source sent fields or types the current schema did not fully accept. That is useful because the data is preserved, but it also means the source contract needs a decision: evolve the schema, keep rescuing, quarantine, or push back on the producer.

`_corrupt_record` is different from `_rescued_data`. Rescued data is still parseable input with unexpected shape. Corrupt records are rows that cannot be parsed cleanly and should be isolated from downstream tables.

Schema evolution mode is a source-contract choice:

- Use explicit schema control for known, fixed contracts.
- Use `addNewColumns` when additive drift is expected and stream restart is acceptable.
- Use `addNewColumnsWithTypeWidening` when compatible type changes are expected.
- Use `rescue` when the table schema should remain stable while preserving unexpected data.
- Use `failOnNewColumns` when new columns should stop the pipeline until a contract owner approves.
- Use `Variant`-style ingestion for highly unpredictable payloads.

Production Auto Loader should use separate checkpoints per source/stream, governed storage paths, source-file metadata, and monitoring surfaces such as `cloud_files_state` and Lakeflow expectations.

## Mistakes / Confusions

- Do not store checkpoints or schema evolution state under the target table directory.
- Do not use one checkpoint for multiple independent source directories.
- Do not put lifecycle deletion policies on checkpoint storage.
- `_rescued_data` should trigger owner review, not silent acceptance.
- `_corrupt_record` is more severe than additive schema drift.
- `addNewColumns` can require an automatic restart after schema inference updates.
- `rescue` keeps the stream running but can hide schema debt if no one reviews rescued columns.
- File events reduce discovery/listing cost, but security and external-location setup must allow them.

## Revision Cards

Q: What does `cloudFiles.schemaLocation` store?
A: Auto Loader schema inference and schema evolution state.

Q: What does the checkpoint location store?
A: Stream progress and discovered-file state.

Q: Why should checkpoint and schema locations be durable?
A: Losing them can force a restart from scratch and may reprocess files.

Q: Why should checkpoint state not be nested under the target table directory?
A: Unity Catalog guidance expects checkpoint and schema state in separate governed storage, not under table data.

Q: What does `_rescued_data` contain?
A: Unexpected fields, type mismatches, case mismatches, and source-file context preserved as JSON.

Q: What does `_corrupt_record` mean?
A: The record itself could not be parsed cleanly and needs isolation.

Q: When should `addNewColumns` be used?
A: When additive source fields are expected and restart-based schema evolution is acceptable.

Q: When should `rescue` be used?
A: When the stream should keep running and preserve unexpected data without evolving the table schema.

Q: When should `failOnNewColumns` be used?
A: When strict contracts require producer or schema-owner approval before accepting new fields.

Q: Why use `cloud_files_state`?
A: To inspect file discovery and processing state for a specific Auto Loader checkpoint.

   Answer: `failOnNewColumns`.

   Answer: `rescue`.

   Answer: `cloud_files_state`.

   Answer: The stream state is corrupted and restart/reprocessing may be required.

   Answer: `_rescued_data` stores parseable but unexpected/mismatched fields; `_corrupt_record` stores records that cannot be parsed cleanly.
7. Why should checkpoints be separate per stream/source?
   Answer: Shared checkpoints can mix state and corrupt exactly-once file tracking.
8. When should Auto Loader be preferred over `COPY INTO`?
   Answer: High file volume, incremental discovery, low latency, schema drift, or checkpointed streaming semantics.
