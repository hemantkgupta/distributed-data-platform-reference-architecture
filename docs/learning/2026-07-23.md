## What I Learned

The Unity Catalog foundation segment is not one topic. It is a production control surface made of object hierarchy, privileges, ownership, storage lifecycle, fine-grained access, compute choice, Delta maintenance, recovery, lineage, monitoring, audit, and cost ownership.

The Associate exam expects enough hands-on fluency to identify the right platform feature or operational surface. The Professional bar is higher: you should be able to defend whether an asset is safe to publish, safe to change, safe to recover, and safe to monitor.

The important readiness shift is from "do we know this feature?" to "can we prove this control exists for this asset?" Examples:

- A PII table without an access policy is blocked.
- A table without lineage evidence is blocked before high-impact changes.
- A warehouse with repeated queueing needs query history and profile review before scaling.
- A job without owner and compute isolation evidence is not production-ready.
- A recovery copy without retention and rollback evidence is a weak recovery plan.

System tables matter because they convert operational behavior into queryable evidence. However, system tables can contain sensitive data and are governed by Unity Catalog. Access should be restricted, and long-lived reports should prefer compact decision summaries over raw exported operational logs.

## PySpark Notes

The notebook uses PySpark to score asset readiness.

```python
assets_df = spark.table("de_learning.platform_assets_day25")
controls_df = spark.table("de_learning.uc_foundation_controls_day25")
```

SQL equivalent:

```sql
SELECT
  asset_name,
  CASE
    WHEN has_owner AND has_lineage AND has_recovery_plan THEN 'READY'
    ELSE 'BLOCKED'
  END AS readiness_decision
FROM platform_assets_day25;
```

Important syntax:

- `spark.table(...)` loads a Delta table as a DataFrame.
- `F.col(...)` references a column inside expressions.
- `isin(...)` is SQL `IN (...)`.
- `withColumn(...)` adds derived point scores and gap labels.
- `F.when(...).otherwise(...)` is SQL `CASE WHEN`.
- `concat_ws(...)` builds a semicolon-separated gap list and skips null values.
- `F.size(...)` counts array entries in the coverage matrix.
- `createOrReplaceTempView(...)` exposes PySpark output to SQL cells.
- PySpark is lazy until `display(...)` or another action executes the plan.

## Mistakes / Confusions

- `SELECT` on a table is not enough without `USE CATALOG` and `USE SCHEMA` on parent objects.
- Row filters, column masks, and ABAC restrictions do not grant access by themselves; object-level privileges still matter.
- A legacy table can exist in the catalog but still be production-blocked because owner, policy, lineage, or recovery evidence is missing.
- SQL warehouse queueing should be diagnosed through monitoring, query history, and query profile before resizing blindly.
- All-purpose compute is convenient for exploration but should not be the default for production jobs.
- System-table data should be governed; exporting it casually can leak sensitive operational metadata.
- Segment review should produce next drills, not just a feel-good summary.

## Revision Cards

Q: What three privileges are generally needed to read a table in Unity Catalog?
A: `USE CATALOG` on the catalog, `USE SCHEMA` on the schema, and `SELECT` on the table or inherited equivalent.

Q: What is a securable object?
A: A Unity Catalog object on which privileges can be granted to a principal.

Q: Why are catalogs and schemas important beyond naming?
A: They are container securables; grants on them can affect current and future children through inheritance.

Q: Why is a PII table without an access policy blocked in the scorecard?
A: Protected data needs an enforceable policy path such as a row filter, column mask, ABAC policy, or controlled view.

Q: What should you inspect before increasing SQL warehouse size?
A: Warehouse monitoring, query history, query profile, queued-query metrics, and spill indicators.

Q: Which system table helps diagnose SQL queries run through warehouses and serverless compute?
A: `system.query.history`.

Q: Which system tables help evaluate job runs?
A: `system.lakeflow.jobs`, `system.lakeflow.job_run_timeline`, and `system.lakeflow.job_task_run_timeline`.

Q: Why should system-table access be controlled?
A: System tables can expose sensitive operational data such as users, assets, lineage, query text, and audit events.

Q: What is the operational meaning of a readiness score?
A: It turns platform concepts into an asset-level publish/change gate with explicit remediation.

Q: What is the next learning segment after Day 25?
A: Data ingestion and loading: COPY INTO, Auto Loader, schema evolution, rescue data, checkpoints, and replay-safe loading.
