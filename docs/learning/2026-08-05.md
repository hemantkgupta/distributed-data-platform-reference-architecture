## Theory Anchors

- The Associate guide dated 2026-05-04 emphasizes hands-on use of the Databricks Data Intelligence Platform, ingestion/loading, PySpark/SQL transformation, Lakeflow Jobs, CI/CD, troubleshooting, monitoring, optimization, and governance/security.
- The live Professional guide dated 2026-07-03 emphasizes production-grade data engineering with Delta Lake, Unity Catalog, Auto Loader, Lakeflow Spark Declarative Pipelines, serverless and classic compute, Lakeflow Jobs, Python and SQL processing, observability, governance, performance, CI/CD, REST API, CLI, and Declarative Automation Bundles.
- COPY INTO is retryable and idempotent; already-loaded source files are skipped even when modified later, so immutable-file discipline matters.
- Auto Loader incrementally processes files with the `cloudFiles` source and stores discovery metadata in checkpoint state to resume after failures.
- Auto Loader schema inference and evolution should use a durable `cloudFiles.schemaLocation`; rescued data preserves missing-schema columns, type mismatches, and case mismatches.
- `cloud_files_state` returns file-level state for Auto Loader or `read_files` streams and should be part of production monitoring.
- File arrival triggers can start Lakeflow Jobs when new files arrive in Unity Catalog volumes or external locations, with debounce and cooldown controls for batch arrivals.
- Lakeflow Connect provides managed and custom ingestion paths for enterprise applications, databases, cloud storage, message buses, and other sources; managed CDC database connectors reduce custom extraction ownership when the source fits.

### 10 Exam-Style Questions

1. A file was loaded with COPY INTO and later modified at the same source path. What should the engineer expect on a rerun?
   **Answer:** The file is skipped because COPY INTO tracks already-loaded files.

2. Where does Auto Loader persist file discovery progress for exactly-once processing?
   **Answer:** In checkpoint state, including scalable file-discovery metadata.

3. Which issue belongs in the rescued data column rather than being silently dropped?
   **Answer:** A column missing from the schema, type mismatch, or case mismatch.

4. A team overwrites an existing file and expects a file arrival trigger to run. What is the safest answer?
   **Answer:** Only new files are a reliable trigger boundary; overwrites need immutable-file discipline and Auto Loader progress tracking.

5. A team needs managed database CDC into Delta with less custom extraction code. Which method is most aligned?
   **Answer:** Lakeflow Connect managed database connector.

6. Which SQL interface can inspect file-level state for an Auto Loader stream?
   **Answer:** `cloud_files_state`.

7. A streaming checkpoint is lost. What should be checked before starting from a fresh checkpoint?
   **Answer:** Whether the target sink can handle bounded idempotent reprocessing.

8. Millions of files per hour require incremental cloud-file ingestion with low listing overhead. Which method fits best?
   **Answer:** Auto Loader with file events and durable checkpointing.

9. Malformed JSON is observed during ingestion with rescue enabled. What should the engineer avoid assuming?
   **Answer:** That malformed JSON is only additive schema drift.

10. Irregular file batches waste always-on compute but can tolerate batch completion latency. Which pattern fits?
    **Answer:** Lakeflow Jobs file arrival trigger with debounce and an AvailableNow ingestion task.

### Mistakes To Revisit

- Do not treat modified source files as safe COPY INTO replay inputs.
- Do not delete checkpoints casually; checkpoint state and target sink idempotency must be reasoned together.
- Do not use rescued data as a generic dumping ground; PII and corrupt payloads require different responses.
- Do not choose continuous compute when file arrival triggers plus AvailableNow satisfy the latency requirement.
- Do not choose Lakeflow Connect only because it sounds modern; choose it when source acquisition ownership and connector fit justify it.

## Revision Cards

1. **Q:** What is the fastest way to tell COPY INTO from Auto Loader in a scenario?
   **A:** COPY INTO fits controlled batch file loads; Auto Loader fits scalable incremental file discovery and checkpointed processing.

2. **Q:** What evidence must accompany an Auto Loader answer?
   **A:** Durable checkpoint, schema location, file-discovery mode, rescue data policy, and monitoring signal.

3. **Q:** What does `cloud_files_state` give you?
   **A:** File-level state for an Auto Loader or `read_files` stream.

4. **Q:** Why is a modified file dangerous after COPY INTO?
   **A:** COPY INTO skips already-loaded files, so source mutation breaks file identity as a replay boundary.

5. **Q:** When does Lakeflow Connect fit better than hand-coded extraction?
   **A:** When a managed or standard connector covers the source, governance, credential, CDC, and maintenance requirements.

6. **Q:** What is the core checkpoint recovery question?
   **A:** Can checkpoint state be restored, or can the sink safely tolerate bounded idempotent reprocessing?

7. **Q:** Why use file arrival triggers with AvailableNow?
   **A:** They reduce idle compute for irregular batches while still processing all currently available files.

8. **Q:** Why quarantine unexpected PII in rescued data?
   **A:** It changes classification, masking, and access requirements before publication.
