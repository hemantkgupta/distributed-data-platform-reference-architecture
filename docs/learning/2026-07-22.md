## What I Learned

Unity Catalog lineage is the production answer to a simple but dangerous question: "What breaks if I change this object?"

Catalog Explorer lineage can show where data came from and where it goes: tables, views, jobs, notebooks, queries, pipelines, and dashboards. It supports impact analysis before changing or deleting a table or column, root-cause analysis when a downstream metric is wrong, and sensitive-data tracking for compliance.

Lineage is permission-aware. A user needs adequate Unity Catalog privileges such as `BROWSE` or `SELECT` to explore object lineage. Workspace objects such as jobs, notebooks, and dashboards also have their own permission checks. This means a limited user might see a masked or incomplete graph.

System tables make lineage operational:

- `system.access.table_lineage` tracks table/path read and write events, including associated entity type.
- `system.access.column_lineage` helps trace column-level flow such as PII propagation.
- `information_schema.tables` and `information_schema.table_privileges` provide metadata and visible grant evidence.
- `SHOW GRANTS` gives object-level privilege evidence when the principal is allowed to inspect it.
- Audit and Lakeflow system tables help connect a lineage edge to the job, query, or user action that produced it.

Principal-level point: lifecycle changes should be blocked by default when lineage shows high-criticality downstream dashboards, jobs, or sensitive-column consumers. The approval artifact should include the graph, affected owners, consumer notifications, validation checks, and rollback plan.

## PySpark Notes

The notebook uses PySpark to compute transitive downstream impact.

```python
edges_df = spark.table("de_learning.lineage_edges_day24")
requests_df = spark.table("de_learning.lineage_change_requests_day24")
```

SQL equivalent:

```sql
SELECT *
FROM lineage_change_requests_day24 r
JOIN lineage_edges_day24 e
  ON r.object_name = e.source_asset;
```

The PySpark loop expands downstream edges up to 3 hops. This is similar to repeatedly self-joining a lineage table:

```python
frontier_df.join(edges_df, current_asset == source_asset)
```

Important syntax:

- `spark.table(...)` loads a SQL table as a DataFrame.
- `join(...)` attaches downstream lineage edges.
- `where(...)` filters first-hop column impact to the changed column when a column is specified.
- `groupBy(...).agg(...)` computes dependency counts and max criticality.
- `withColumn(...)` adds `blast_radius`, `change_decision`, and `evidence_required`.
- `F.when(...).otherwise(...)` is SQL `CASE WHEN`.
- `createOrReplaceTempView(...)` lets SQL cells query PySpark output.
- PySpark remains lazy until `display(...)` or another action runs.

## Mistakes / Confusions

- Lineage is not only a diagram; it should produce approval and notification tasks.
- A direct dependency count is insufficient because impact can be transitive through silver/gold tables and views.
- Column-level changes should filter impact by affected column, then continue downstream from impacted targets.
- Permission-aware lineage can be incomplete for users without enough Unity Catalog or workspace permissions.
- System lineage tables retain a rolling history window, while Catalog Explorer has different retention behavior.
- Some workloads do not emit complete lineage, such as unsupported job-submit patterns, RDDs, global temp views, path-based reads, or some private pipeline cases.
- Information schema is metadata visibility, not full operational lineage.
- High-criticality dashboards and sensitive data flows should block lifecycle changes until owners approve.

## Revision Cards

Q: What is Unity Catalog lineage used for before changing a table?
A: Impact analysis: identify downstream tables, jobs, dashboards, notebooks, queries, and columns that depend on the object.

Q: Which system table stores table-level lineage events?
A: `system.access.table_lineage`.

Q: Which system table stores column-level lineage events?
A: `system.access.column_lineage`.

Q: Why is lineage permission-aware?
A: Users only see lineage for objects and workspace assets they have enough privileges to browse or access.

Q: Why is transitive impact important?
A: A source table can affect dashboards through several hops, such as raw -> silver -> gold -> view -> dashboard.

Q: What should happen if a proposed drop affects high-criticality dashboards?
A: Block the change until consumer owners approve, validation is planned, and rollback is documented.

Q: What should happen if a column drop affects a sensitive data flow?
A: Block or route to privacy review and downstream redesign.

Q: What evidence belongs in a lifecycle change approval?
A: Lineage graph/query result, affected owners, dependency count, criticality, sensitive-flow count, notification plan, validation query, and rollback plan.
