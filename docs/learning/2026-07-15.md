## What I Learned

Unity Catalog access is not one privilege.

For a user to query a table or view, three things usually matter:

```text
USE CATALOG on parent catalog
USE SCHEMA on parent schema
SELECT on the table or view
```

For writes:

```text
USE CATALOG
USE SCHEMA
MODIFY on the table
```

For volumes:

```text
USE CATALOG
USE SCHEMA
READ VOLUME or WRITE VOLUME on the volume
```

For functions:

```text
USE CATALOG
USE SCHEMA
EXECUTE on the function
```

Usage privileges let a principal traverse the namespace. They do not grant data access by themselves. Object privileges grant the actual operation. Inherited grants can apply broadly to current and future child objects, which is useful for platform teams but dangerous when a schema contains sensitive base tables.

Principal-level point: access reviews should produce evidence. The review should answer who requested access, what action they attempted, which privileges were required, which privileges were missing, whether access was allowed, and what remediation is needed.

## PySpark Notes

The notebook uses PySpark to compute effective access.

```python
effective_grants_df = (
    exact_grants_df
    .unionByName(schema_inherited_grants_df)
    .unionByName(catalog_inherited_grants_df)
    .dropDuplicates(["principal", "privilege", "effective_object_name"])
)
```

SQL equivalent:

```sql
SELECT principal, privilege, object_name AS effective_object_name FROM direct_grants
UNION ALL
SELECT g.principal, g.privilege, o.object_name
FROM schema_grants g
JOIN objects o
  ON g.object_name = o.schema_name
WHERE g.applies_to_descendants = true;
```

The decision logic expands each access request into required privileges, left-joins to effective grants, and groups back to one row per request.

Important syntax:

- `spark.table(...)` loads a SQL table into a DataFrame.
- `unionByName(...)` stacks rows from DataFrames with matching column names.
- `join(..., how="left")` checks whether a required privilege has a matching grant.
- `withColumn(...)` derives required object names, missing requirements, and risk notes.
- `groupBy(...).agg(...)` converts many requirement rows into one decision row.
- `F.collect_set(...)` gathers missing requirements and grant evidence without duplicate strings.
- Nothing runs until an action such as `display(...)`.

## Mistakes / Confusions

- `USE CATALOG` and `USE SCHEMA` are prerequisites, not data access.
- `SELECT` on a view still fails if the user cannot use the parent catalog/schema.
- Schema-level inherited `SELECT` can unintentionally expose future tables.
- Base-table `SELECT` on restricted data should be an exception, not the default path.
- Volumes use `READ VOLUME` and `WRITE VOLUME`, not table `SELECT` or `MODIFY`.
- `MANAGE` is about administration; it is not the normal reader/writer path.
- A denied request should become a remediation decision, not a vague support ticket.

## Revision Cards

Q: What privileges are typically needed to query a table?
A: `USE CATALOG`, `USE SCHEMA`, and `SELECT` on the table, or an inherited `SELECT` that applies to the table.

Q: What privileges are typically needed to query a view?
A: `USE CATALOG`, `USE SCHEMA`, and `SELECT` on the view.

Q: Does `USE SCHEMA` grant data access?
A: No. It lets the principal traverse or see the schema namespace; object access still needs privileges like `SELECT`.

Q: Why is inherited schema-level `SELECT` risky?
A: It can apply to current and future child tables, including restricted base tables.

Q: Why prefer a view for analytics readers?
A: A view can expose a stable, governed, masked, or filtered surface while keeping the base table restricted.

Q: What privileges are used for volumes?
A: `READ VOLUME` and `WRITE VOLUME`, plus `USE CATALOG` and `USE SCHEMA`.

Q: What should an access decision record contain?
A: Request, principal, action, object, required privileges, missing privileges, allow/deny outcome, evidence, and remediation.

Q: What is the principal-level remediation for broad base-table reads?
A: Revoke or avoid base-table `SELECT`; grant `SELECT` on a governed view unless an exception is approved.
